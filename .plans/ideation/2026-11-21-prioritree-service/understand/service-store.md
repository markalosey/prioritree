## (1) THE RACE WINDOWS — each walked at the bytes

- **register's scan-mint-write**: the window spans the glob (_scan_next_run_number) to the file's creation inside _append_line — the TOCTOU. Two concurrent registers: both scan (both see max N), both mint RUN-{N+1}, both open-append the SAME path (open("a") on an absent file creates); each writes one complete flushed manifest line — no torn bytes, the file ends with TWO manifest lines, order free. The failure fires at the NEXT load: the second line's kind == "manifest" → the refusal "a duplicated manifest line". Secondary: both registers return handles with the same stem but each door minted its own in-file run_id — the two handles alias one file.
- **the load-act-append across requests**: each request's load rebuilds a FRESH door; the vote_id minted per-store max+1 over that ledger's own live size — "two ledgers mint independently" the votes.py named form. Two concurrent casts both census k, both mint VOTE-{k+1}, neither acks (each store's dedup index holds only its own k lines), both append — the file gains two lines carrying the SAME vote_id; the next load's pre-pass refuses at the second ("mint order, no gaps, no dups"). Even a byte-identical crash-retry pair doubles (the pre-pass fires before the re-cast dedup could absorb). Exactly the store's docstring pre-named surface: "a concurrent double-write surfaces at the next load as the id-sequence refusal — loud, never silent."
- **the read verbs under a concurrent writer**: two windows — register's create→flush gap (the file exists but empty: "no manifest line first — the file is empty"), and a cast's append in flight (the tail read without its newline fires the crash-tail refusal — a FALSE "corrupt file" on a healthy run; a torn JSON tail fires the parse refusal). The mechanism named: the read must either lock or tolerate the tail.

## (2) THE LOCK'S FORM

- **Re-entrance**: the seam is FLAT — five verbs 1:1 with the routes, each = one acquisition wrapping one load+act composition; no seam verb calls another seam verb, and Persist's own verbs never touch a seam lock. **threading.Lock suffices; RLock buys nothing** (re-entrance would only license accidental nesting the 1:1 route form rules out). **Home**: the seam object constructed once with the lock + the store home (store-as-parameter; the app.state injection at the face unit). **Granularity**: ONE process-wide lock — the whole act inside, all runs serialized through one critical section (the multi-process widening banked under the single-worker launch). **Reads lock too** — the false-refusal windows price it; the simplest correct form: EVERY seam verb locks.

## (3) THE INTERLEAVING TESTS' MECHANISMS

- In-process threads, stdlib only (zero new deps at this unit): N callables × M seam-casts on one run; the join the barrier, the assertions after. **The property**: (1) every cast landed — the reloaded census count == N×M exactly; (2) the ids unique — the id SET == {VOTE-0001..VOTE-{N×M}}; (3) the file loads clean — the fresh Persist.load IS the oracle (the pre-pass re-validates every trigger; any interleaving damage refuses there). **Determinism**: the interleaving ORDER free (the scheduler owns thread arrival), the OUTCOME deterministic — the lock serializes WHOLE acts, so the file is a serialization of whole acts: the line ORDER the only free variable (plus the recorded_at stamps — named and excluded, the honesty pin); the count and the id SET exact under any schedule. The threads must cast THROUGH the seam — raw Persist.cast from two threads is exactly the failure.

## (5) THE GIL — answered honestly

- **The GIL does NOT make load→act→append atomic**: (a) the interpreter preempts BETWEEN bytecodes — the load→rebuild spans thousands of boundaries, so two requests can both complete load before either casts (the exact doubled-mint form); (b) the file I/O releases the GIL around the read/write syscalls — the bytes travel outside the GIL's protection; (c) even the in-memory mint is multi-bytecode — a classic preemption seam, and each request's store is a SEPARATE ledger anyway (independent mints by construction). On CPython the lock is load-bearing exactly as on a free-threaded build: the ruling's "single-writer contract held BY CONSTRUCTION" rests on the LOCK, never on the GIL — the GIL serializes bytecodes, not acts.
