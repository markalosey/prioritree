## (1) THE RECONSTRUCTION CHAIN

- **What must cross** (the file's schema = the core's value types minus the mint-and-stamp fields): the manifest's items (the (id,label) rows, payload order), operator (id, question, verdicts), quorum — these three ARE register_run's signature. Per vote, the seven cast fields in mint order — run_id, pair, winner, comparator_id, comparator_class, notes, supersedes — these ARE cast_vote's signature.
- **What rebuilds** (the load, four steps): (1) fresh Registry() + Session(registry) (the ledger built internally — one registry behind both stores by construction); (2) register_run(items, operator, quorum) — a fresh registry mints RUN-0001; (3) per saved record in file order, cast_vote's seven args; (4) census/tally read back publicly.
- **The dedup at replay**: the key's members are the seven cast fields ONLY — neither stamp nor vote_id is a member. A faithful replay into a fresh ledger MISSES every line (empty index) and MINTS fresh records, acknowledged=False. The loud-ack path fires only on a DUPLICATE: a byte-identical line twice (a crash-retry's double-write) is absorbed loudly, never double-counted (R9); a changed verdict is a legal new record.
- **Vote-id minting's sequential stability**: the mint is per-STORE max+1 over the FLAT store holding all runs' votes. Line i (0-based) of a single-run file re-mints VOTE-{i+1:04d}: ids equal the file's iff the original ledger held only that run's votes in that order (the per-run store, fresh session per run — the acceptance unit's own shape). Id stability is LOAD-BEARING twice: stage 5 checks the supersedes target live in the REBUILT store, and the tally's exclusion set matches supersedes strings against vote_ids — a shifted re-mint orphans every correction at replay.
- **Run-id minting across a fresh registry**: mint-only — no id argument exists. The re-minted id equals the file's id iff the replay re-registers the run at the same registry position: a single-run store round-trips only RUN-0001; any partial replay re-mints from RUN-0001 and the saved id does not survive — the file's name, not the registry's handle, is the run's cross-process identity. (The tally is indifferent: the replay re-casts under the LIVE handle.)

## (2) THE CLOCK-STAMP DIVERGENCE — the honesty pin's ruled form

- Two stamps, both minted at now inside the door (registered_at, recorded_at — UTC µs ISO). NO public verb carries a stamp across — neither op takes a time argument; the session stamps nothing. At replay both re-stamp.
- **What IS byte-identical** (the field-selected surface): the census MAPS (per_pair_counts/per_item_counts, built per call from the records' pairs alone); the vote IDS (under the order-preserving single-run replay); the seven cast fields per record; and the TALLY (tally_votes consumes only the manifest's items/quorum/run_id and the records' run_id/pair/winner/supersedes/vote_id — the stamps never enter).
- **What re-stamps — named and excluded**: registered_at (at re-register) and recorded_at (at each re-cast). The census's vote_log is therefore NOT byte-identical. The precedent's ruled form verbatim: "byte-reproducibility asserted over the field-selected clock-free surface only (the wall-clock stamps named and excluded by construction), never the impossible full-log byte-identity" (acceptance.py:24-27).

## (3) THE WRITE PATH — save-at-cast vs save-at-exit

- The core owns NO file I/O. The FILE append is OUTSIDE the core's atomic window — the store owns the seam between the in-memory append and the file's line. Crash between the ledger's write and the file's append: the load sees the file minus the tail — the census rebuilds from the file, next_pair re-serves the pair, the re-judge a NEW sample; the loss is invisible to the load (the file is the truth) and bounded by the save ruling. The truncated log: a crash mid-append leaves a half-written last line — the refusal path fires, never a silent skip.
- **THE TRADE**: save-at-cast costs one line-append per judgment and bounds the crash loss to ≤ 1 cast (the durability verb the wrapper's own); save-at-exit costs nothing mid-session but the crash window is the WHOLE session. The capture point either way is public: the record rides cast_vote's return — the CLI's own composed casts.

## (4) THE CORRUPT-FILE REFUSAL PATHS

- Each in the family's three-field grammar, each raised BEFORE any record rebuilds (the before-any-byte-lands school): the JSON parse failure (expected = a well-formed record line; found = the line number + the parser's message verbatim; next_action = inspect and repair); the schema-violating record (the seven-field grammar verbatim; comparator_class ∈ {human, llm}); the orphaned supersedes (every reference resolves to an EARLIER line, same run, same pair — an orphan refuses loudly naming the id and its line; stage 5 also forecloses the tally's silent hazard). NEVER a silent partial load: the store's OWN pre-pass (parse + validate the whole file) runs before the first re-cast — a cast-time refusal landing MID-replay with earlier casts already rebuilt would be a silent partial load.

## (5) THE FENCE

- **CONFIRMED from the bytes**: the reconstruction composes public only — Registry(), Session(registry), register_run, cast_vote; the stores stay private. **The door is SUFFICIENT on the read side**: register_run's return carries the manifest whole; cast_vote's return carries the record whole; read_vote_state returns the census with the full frozen log publicly — "no public read of the vote records" is false; the census IS that read.
- **The named gap — the write side's fidelity ceiling**: no public verb restores a stamp (both mint at now) and none sets a run_id (mint-only) — a full-byte round-trip is unrepresentable through the door; the pin must field-select (the acceptance precedent). **The composition's implication, confirmed**: the write path captures at cast time from the cast's own return (the record is in hand at the moment of the cast); read-back is not forbidden by the fence but re-derives the same public bytes at extra cost while the crash window stays open — capture-at-cast is the window-minimal composition, and the returned record is its capture point.
