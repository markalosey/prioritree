## (1) THE CENSUS — what exists

- **The door's exact public surface**: Session(registry) — the registry injected, VoteLedger(registry) constructed internally (ONE Registry behind both stores by construction); register_run(items, operator, quorum=1) → (run_id, RunManifest, count); next_pair(run_id, seed=None) → (item_a, item_b, count) or ExhaustedQueue (the DONE signal, suffix-free); cast_vote(run_id, pair, winner, comparator_id, comparator_class, notes?, supersedes?) → (vote_id, VoteRecord, count, acknowledged); read_vote_state(run_id) → VoteCensus; tally_rank(run_id) → TallyResult or TallyRefusedError verbatim. ONE refusal grammar at the surface: VotesRefusedError(expected, found, next_action). The core stamps its own boundary: "no files, no subprocess, no DB; SINGLE-PROCESS by contract" — persistence lands wholly at this tier.
- **The state that must cross the exit** — two primary structures + one derived: Registry._manifests (dict[str, RunManifest]); VoteLedger._votes (dict[str, VoteRecord], flat across runs, filtered per run at read); VoteLedger._dedup DERIVED (the key members ARE the record's fields — the gate rules it "rebuilt at load"; the file need not carry it). VoteCensus derives per call — never persisted.
- **Reconstruction inputs (what a save must capture)**: RunManifest — run_id; items (the (id,label) rows, payload order preserved); operator (id, question, verdicts — the default WEAK_ORDER_TRIPLE {prefer-a, prefer-b, tie}); quorum; registered_at (UTC µs ISO). VoteRecord — vote_id (VOTE-{####}); run_id; pair (canonical, item_a < item_b); winner (from the run's OWN declared set); comparator_id; comparator_class ({human, llm}); recorded_at (UTC µs ISO); notes; supersedes. The mints: RUN-{####} and VOTE-{####} both per-store max+1, mint+append one synchronous act.
- **The replay's laws** (the dedup/revote/supersede semantics): byte-identical re-send → the LOUD ack (the original handle, the original record, UNCHANGED count, acknowledged=True); changed verdict → a NEW record (both count); correction → a NEW record citing the old via supersedes (both stand; the tally walks the link); chains linearly. The supersede ground truth: target live, same run, same pair.
- **The in-tree JSONL precedent** (the friction ledger): append-only; one flat JSON object per line, self-describing; ISO-8601 µs UTC stamps; handle-keyed references. Sibling properties: line-appendable (no whole-doc rewrite), human-inspectable.
- **The floor**: dependencies = [] (json/argparse stdlib); ruff ALL + named per-file rulings only; pyright strict, reportUnnecessaryTypeIgnoreComment = error; no [project.scripts] yet — the command-face unit wires it.

## (2) THE GAPS the brief must pin — as questions

1. **The reconstruction seam (load-bearing)**: byte-identical round-trip requires the reload to land FROZEN values — but no public verb lands pre-minted state: register_run re-mints + re-stamps; cast_vote re-stamps AND its dedup ACKS byte-identical re-sends instead of appending — op-replay cannot rebuild the log; recorded_at rides inside the census's vote_log. Through-the-door reconstruction is unrepresentable at the FULL byte level and the core is untouchable — the brief rules the field-selected equality surface (the acceptance unit's own precedent).
2. **The store's home path**: where does the flat store live? A named constant, content-in-configuration.
3. **The file format**: one file or two (manifest + votes)? A single JSON doc cannot "append per cast" — the JSONL precedent is the in-tree append form. How do frozen types serialize/restore type-exact (Pair, frozenset, tuple → the byte-identical census), and is the global vote mint order preserved?
4. **Run-id stability**: the mint reads live-store size — post-load, the next register must continue the sequence. Does the load validate the id sequence (refusing gapped/duplicated ids as corrupt) or trust the file's names?
5. **The clock-stamp divergence's honesty pin**: registered_at/recorded_at are process-time stamps; byte-identical census forces verbatim restore — stamps ride the file as data, new mints stamp fresh; the brief pins the equality assertion and names any divergence honestly.
6. **The write path**: save-at-cast vs save-at-exit — each cast IS its own process under the subcommand shape; when do bytes land, and what does a failed write do — lost, or refused loudly?
7. **The corrupt-file refusal**: the form is ruled (three fields, the repair path named, never a silent partial load); the brief pins the trigger set (parse failure, truncation, missing fields, wrong types, id-sequence violations) and the type: a new family member or a reuse.
8. **The atomicity window**: the crash-between-writes state — the write's own window (truncate+rewrite vs temp+rename), the ordering legality (a registered run with zero votes is legal), the concurrent-invocation window (does this tier document single-writer or refuse?).

## (3) THE LAWS RIDING

- **The fence**: no persistence verb added to the five-op door; the store composes the door ONLY; the core stays in-memory, zero-dep, untouched.
- **Zero runtime deps** (json stdlib); **the naming law** (a new symbol's name = the first word of its act-statement); **content-in-configuration** (the store's home path — every structural literal — a named module-level constant); **the no-shell law**; **five-field docstrings** (Purpose/Refuses when/Re-run/Touches/Provenance — every public symbol).
- **Riding with them**: the refusal family grammar (expected/found/next_action, the Error-suffix lineage; ExhaustedQueue suffix-free the non-refusal precedent); store-as-parameter containers, never module-level singletons — test isolation; mint+append in one synchronous act (the atomic-mint discipline the store's writes ride); the zero-findings bar, zero ignores (a new ignore is a ruling at the brief); one-commit-per-increment.
