## 1. The win-rate chain

**1.1 THE INPUT — the honest seam.** [DERIVED over STATED] Op 5 tally_rank(run_id) composes two public reads: the manifest via read_manifest (quorum, ids, operator.verdicts) and the vote state via read_vote_state — both owning-unit public ops (the siblings law). The census carries neither manifest nor quorum, so the manifest read is load-bearing. **The census's count fields are NOT the tally's counts**: read_vote_state increments per-pair/per-item for EVERY record, superseded included, while the tally's weighting excludes them — the tally consumes ONLY census.vote_log (the raw multiset, mint order) and re-derives weighted counts. The census is the audit view (never refuses on coverage); the weighting is op 5's own ("U3 exposes the references, U4 rules the weighting — the Parnas fold's other half"). **"The tally reads only votes" scopes the RANKING**: identical votes ⇒ identical rank; the quorum is policy-as-data read by the GATE, not the ranking — same votes under a different quorum ⇒ same rank, different verdict. The pure core (count→rank) vs the policy shell (gate) is THE seam.

**1.2 THE WEIGHTING PASS.** [STATED policy / DERIVED mechanism] Ruled: the old stands in the log, excluded by the tally's weighting; the policy lives inside the tally module. **The exact exclusion set: E = { r.supersedes | r ∈ the run's log, r.supersedes ≠ None }** — the set of cited handles. Records with vote_id ∈ E are excluded; the rest are counted — the correction counted, the superseded excluded. **No chain walk needed**: for 0001←0002←0003, 0001 and 0002 are both cited (∈ E), 0003 the uncited tip — every chain's interior is E, its end counted. Double-cite (two corrections citing one original): the write gate checks target live/same-run/same-pair only — set semantics exclude the original once, count both corrections. Cross-run citations unrepresentable — E is per-run by construction. The dedup half holds vacuously upstream (the loud ack means no byte-identical duplicate can exist). Named philosophy: **one judgment = one unit of weight** ("zero weight pollution") — hence the coverage legs also ride the weighted counts.

**1.3 THE COUNTING PASS.** [STATED mapping] Positional over the canonical pair (item_a < item_b strict): prefer-a ⇒ item_a +1 win / item_b +1 loss; prefer-b ⇒ item_b +1 win / item_a +1 loss; tie ⇒ both +0.5 tie, both +1 comparison (a tie still compares). [DERIVED] The mapping is total over the only legal declared set (the registry refuses any verdict set but the triple; U3's stage 4 refused any winner outside the declared set) — no unknown token can reach the tally; no verdict re-validation owed. Per item: integer wins/losses/ties; comparisons_i = wins+losses+ties (each counted record touches each member exactly once).

**1.4 THE SCORE.** [STATED] score_i = (wins_i + 0.5·ties_i)/comparisons_i. [DERIVED] Division safe by gate order: the zero-coverage leg fires before any ranking emits — every scored item has comparisons ≥ 1.

**1.5 THE RANKING.** [STATED] Sort by score descending, deterministic id tie-break; equal scores form shared-rank groups rendered in stable id-order. [DERIVED] Sort key (−score, id) — total because ids are unique; groups = maximal equal-score runs. Float grouping is faithful: IEEE division correctly rounded, so equal rationals ⇒ equal doubles — BUT the census's cross-multiplied-integer comparison is the exact form (floats can collapse distinct rationals).

**1.6 THE EMISSION (frozen shape).** [STATED] The ranked whole (tie groups, stable id-order) + per-item wins/losses/ties + coverage counts + the coverage verdict + the algorithm version stamp. Per R12: the emission carries the counts and the verdict — "scores beyond counts ride later with the probabilistic tally" — the score is the internal ordering key; consumers recompute it exactly from the emitted counts. Write target: nothing. The version stamp a constant. [OPEN] the exact field names, the stamp string.

## 2. The coverage gate's three legs

[STATED] DONE = no zero-coverage item ∧ connected graph ∧ per-pair quorum met per the manifest's own data; any leg unmet ⇒ SAFE HALT; strictly binary; never a partial ranking; well-defined at every prefix; the expected pair set CITED from schedule_pairs, never re-derived.

- **Leg 1 — zero-coverage**: an id with weighted comparisons_i = 0. [DERIVED invariant] census ⟺ weighted agreement here: an excluded record implies a counted correction on the SAME pair — exclusion cannot orphan an item.
- **Leg 2 — connectivity, the honest form**: [DERIVED] the graph over the ACTUAL counted votes — nodes = manifest ids, edges = distinct pairs with ≥1 counted vote. Pair-set arithmetic cannot answer it (connectivity a global graph property no per-pair predicate composes); the honest price a traversal — BFS or union-find over the voted pairs. The refusal must name the components, which the traversal yields as data, rendered in sorted id-order. A boolean-only shortcut refused by the ruling's own text.
- **Leg 3 — quorum**: every pair in schedule_pairs(manifest ids) must have WEIGHTED count ≥ manifest.quorum. [DERIVED] A corrected pair counts its judgments once — k=2 with one vote + its correction: weighted 1 < 2 ⇒ unmet, where the census's raw 2 would lie.
- **The legs nest** [DERIVED]: quorum-met ⇒ every pair voted ⇒ the complete graph ⇒ connected ⇒ no zero-coverage (n ≥ 2 guaranteed by U1's refusal). Any failure implies under-quorum pairs exist; a zero-coverage item IS a singleton component. The three test edges distinct by their DEEPEST failure: quorum-only (leg 3 alone), disconnected (legs 2+3), zero-coverage (legs 1+2+3). The gate names the deepest structural truth.
- **The SAFE-HALT text** [STATED grammar / DERIVED content]: the typed refusal, expected/found/next-action, raised never returned. expected: the coverage whole in the run's own numbers. found: the actual state — zero-coverage ids (sorted), the components (sorted id-sets), the under-quorum canonical pairs with weighted counts. next_action: the exact closing pairs — for components C1..Cm (sorted by min id), the m−1 bridging pairs (min(C1),min(C2)), then (min(C1∪C2),min(C3)), … — a spanning tree across components; for quorum-only gaps, the under-quorum pairs themselves, each k−count votes short. Two gap KINDS named distinctly: connectivity needs NEW comparisons; quorum needs MORE VOTES on existing pairs. [OPEN] the exact strings.

## 3. The purity properties

- **Order-independence** [DERIVED under the STATED ruling]: all accumulation INTEGER (exact, commutative, associative); the only non-integer arithmetic one correctly-rounded division per item from its own integers — no sequential state, no order-dependent update (the Elo refusal). Any permutation of the same multiset ⇒ identical integers ⇒ identical scores ⇒ identical (−score, id) sort ⇒ byte-identical emission.
- **No environment reads** [STATED]. [DERIVED consequence] the emission carries NO timestamp — the records' recorded_at stamps are provenance the tally never reads into scoring or emission; the version stamp a constant, not a clock.
- **The prefix property** [STATED]: at every vote-count the function returns a defined value — the whole or the refusal; a refusal IS a defined outcome. The purity dividend: identical votes ⇒ identical rank, so rank divergence between two copies is store-divergence proof.

## 5. The edges + the test edges

1. **Empty log**: every item zero-coverage, n singletons, every pair 0 < k ⇒ SAFE HALT naming all. The census refuses nothing; the gate is the refusal's only home. 2. **Single vote, n=2**: k=1 met, connected ⇒ DONE — the minimal whole (1.0/0.0, two singleton groups). 3. **Single vote, n=3**: third item isolated ⇒ SAFE HALT (isolated item named, two components). 4. **Full-coverage DONE**: hand-computed known-answer fixtures. 5. **Quorum-unmet, pure leg-3**: n=3, all pairs ≥1, k=2, one pair at 1 ⇒ SAFE HALT naming that pair, 1 vote short. 6. **Disconnected, two components**: n=4, {a,b} and {c,d} voted within ⇒ SAFE HALT naming both components and the bridging pairs. 7. **The cycle**: one group of 3 at 0.5, cycle named, DONE. 8. **Tie-break determinism**: equal scores share a group, stable id-order within; re-run byte-identical. 9. **Supersession exclusion**: 0001 superseded by 0002 ⇒ 0001 excluded, 0002 counted, both in the log; the chain ⇒ only the tip counted; the k=2 quorum view counts a corrected pair once. 10. **Byte-identical re-run**: same multiset, two cast orders ⇒ identical emissions. 11. **Every-prefix property**: scripted sequence, tally at each prefix — a defined outcome each time, never partial, never silence. 12. **The weighted-vs-census seam**: a correction makes census per-pair 2 but weighted 1 — the fixture pins the weighting AND documents the seam: census counts unweighted by design; the weighting lives in U4 alone; any quorum-sensitive consumer (U5's consult) rides U4's view — a seam for the session brief, named here.
