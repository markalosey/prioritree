## §3 THE ALGORITHM — the chain (weight → count → gate → score → rank → emit)

**3.1 THE WEIGHTING PASS** (the policy INSIDE this module — the Parnas fold's other half). The run filter first: records with `run_id != manifest.run_id` dropped (the composition hands `census.vote_log`, run-filtered by construction; the function applies the same filter — the census's own discipline, cited). **The exclusion set: E = {r.supersedes for r in the run's log if r.supersedes is not None}** — the set of CITED handles. Counted = the records with `vote_id not in E`; the correction counted, the superseded excluded. **No chain walk**: for 0001←0002←0003, both 0001 and 0002 are cited (∈ E) — every chain's interior is E, its uncited tip counted. **The fork [PROPOSED: ratified — set semantics]**: two corrections citing one original (U3 does NOT refuse it) — the original excluded ONCE, BOTH corrections counted. Reason: E is a set by construction (the comprehension dedups); a per-cite subtraction would double-subtract; both corrections are live judgments — one judgment = one unit of weight. The revote class needs no weighting (a changed verdict is a new sample, both count — R9); the dedup class none (U3's loud ack means no byte-identical dup can exist — vacuous); cross-run citations unrepresentable (U3's same-run check).

**3.2 THE COUNTING PASS.** Positional over the canonical pair (`item_a < item_b` strict — U2's construction; the mapping's safety bought upstream: U3's swapped-citation refusal, U2's id-sorted form): `record.winner == PREFER_A` ⇒ item_a +1 win, item_b +1 loss; `== PREFER_B` ⇒ item_b +1 win, item_a +1 loss; `== TIE` ⇒ both +1 tie (a tie still compares). Per item: INTEGER wins/losses/ties only — exact, commutative, associative (the purity ground); comparisons_i = wins + losses + ties (each counted record touches each member exactly once); weighted per-pair count: +1 on the pair per counted record. No verdict re-validation (the mapping total over the only legal declared set — U3's stage 4 the authority, the precondition cited; never re-policed, U2's precedent).

**3.3 THE SCORE.** score_i = (wins_i + 0.5·ties_i)/comparisons_i. **Division safe by gate order** — the gate fires BEFORE any ranking emits, so every scored item has comparisons ≥ 1. One division per item from its own integers — the only non-integer step, order-independent by construction.

**3.4 THE RANKING.** Equal scores ⇒ ONE shared group (the group form refuses to order what the data cannot); groups = maximal equal-score runs. **THE COMPARISON [RULED exact — the census (c)]: cross-multiplied integers, never floats** — item i ranks above j iff (2·wins_i + ties_i)·comparisons_j > (2·wins_j + ties_j)·comparisons_i (score = (2w+t)/(2c); correctly-rounded floats can collapse mathematically-distinct rationals into a spurious shared group — the fragility named, foreclosed by construction). [PROPOSED: the mechanical carrier — stdlib `fractions.Fraction`: the sort key (−Fraction(2·wins + ties, 2·comparisons), id); Fraction's rich comparisons cross-multiply the integers internally — the exact form; the group boundary tests Fraction equality — one mechanism, never two.] Reason: exact by construction (no float anywhere in the ordering), stdlib-only, and the id limb keeps the key total (ids unique). The (−score, id) key yields ids sorted within each group by itself.

**3.5 THE ORDER OF THE CHAIN.** weight → count → **GATE** → score → rank → emit: the gate precedes the score (division safety) and the emission (never a partial ranking) — the strictly binary terminal states are a property of the chain's order, not of a wrapper.

## §4 THE COVERAGE GATE — the three legs, the binary states, the SAFE-HALT bytes

**The datum [RULED]: the WEIGHTED counts** — the tally builds its own; the census's counts are the unweighted audit view, NEVER the gate's (a corrected pair at k=2: census 2, weighted 1 ⇒ unmet — the census would lie).

- **Leg 1 — zero-coverage**: any manifest id with weighted comparisons_i == 0 → fail; the isolated ids named, sorted. [Cited invariant: an excluded record implies a counted correction on the SAME pair — exclusion cannot orphan an item; census ⟺ weighted agreement here.]
- **Leg 2 — connectivity**: nodes = manifest ids; edges = the expected pairs with weighted count ≥ 1 (the comparison graph is the graph of comparisons made; quorum shortfalls ride leg 3 — the legs stay orthogonal). [PROPOSED: union-find over the ≥1-counted pairs] — reason: deterministic, near-linear, and the component partition falls out as data (a boolean-only shortcut is refused by the ruling's own text — R12/op 5 name the isolated items/components). Components rendered ids-sorted within, ordered by smallest id.
- **Leg 3 — quorum**: EVERY pair in the cited expected set — `schedule_pairs` over the manifest ids, CALLED never re-derived (FR-MEM-0001's lesson) — must reach weighted count ≥ manifest.quorum.

**The composition [PROPOSED]: the legs AND-composed; the refusal reports ALL failing legs' findings** (the audit honesty). Well-defined at EVERY coverage prefix (a refusal IS a defined outcome). **A cycle never blocks** — the legs are coverage legs only; a Condorcet triple at full coverage is DONE with the cycle named (R11). **The deepest-leg naming** (the nesting: quorum-met ⇒ every pair voted ⇒ the complete graph ⇒ connected ⇒ no zero-coverage; n ≥ 2 guaranteed by U1's refusal): the found renders exactly the failing legs — quorum-only → leg 3's section alone; disconnected → legs 2+3; zero-coverage → legs 1+2+3 — the gate names the deepest structural truth, and the AND-reporting makes the nesting visible rather than implicit.

**The terminal states [RULED — R12, strictly binary]:** all legs met → `TallyResult` (DONE); any leg unmet → `TallyRefusedError` (SAFE HALT). **Never a partial ranking dressed as whole; never an empty list** (n ≥ 2 by U1's precondition — an emission carries ≥ 1 group, a refusal names ≥ 1 finding).

**The SAFE-HALT text — the three fields' exact bytes [PROPOSED, drafted verbatim]:**

- **expected** (constant shape, the run's own numbers): `"the coverage gate met: no zero-coverage item, the comparison graph connected, every pair at quorum k={quorum}"` — {quorum} = manifest.quorum.
- **found** (each section present only when its leg fails; sections joined by "; "): leg 1 → `"zero-coverage items: {ids, ', '-joined, sorted}"`; leg 2 → `"components: ({ids of C1}), ({ids of C2}), …"` (ids-sorted within, components ordered by smallest id); leg 3 → `"under-quorum pairs: ({a}, {b}) {count} of {k}, …"` (canonical pairs in id-sorted order, each with its weighted count).
- **next_action** (each section present only when its gap kind exists; joined by "; "): connectivity (legs 1-2) → `"cast the bridging pairs: ({min C1}, {min C2}), ({min C1∪C2}, {min C3}), … — connectivity needs NEW comparisons"` — **the closing-pairs rule**: components C1..Cm ordered by smallest id, the m−1 bridges (min(C1), min(C2)), then (min(C1∪C2), min(C3)), … — a spanning tree across components (the census (f)'s alternative — every isolated item's full untouched pair set — refused as noise; one bridge closes BOTH the singleton's zero-coverage and the graph's disconnection); quorum (leg 3) → `"cast the missing votes: ({a}, {b}) needs {k−count} more, … — quorum needs MORE VOTES on existing pairs"`. **The two gap kinds named distinctly** — new comparisons vs more votes — never conflated.
